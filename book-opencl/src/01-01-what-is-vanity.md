# 1.1 什么是 vanity 公钥

这节讲清楚我们要做的东西到底是什么，以及它为什么只能靠「暴力碰运气」。

## WireGuard 的公钥长什么样

WireGuard 用一对密钥标识一台机器：私钥自己藏着，公钥发给对端。两个 key 都是 32 个字节，用 base64 编码后显示为 44 个字符：

```text
私钥: 2A7fV3k...（44 字符，以 = 结尾）
公钥: xTIBA5r...（44 字符，以 = 结尾）
```

公钥是从私钥**单向**算出来的（怎么算，3.2 节讲）。这个单向函数是密码学安全的，意味着：你没法「设计」一个公钥然后反推私钥，只能随机生成私钥、算出公钥、看看长什么样。

## vanity = 好看的

普通公钥是一串乱码，不好认也不好念。vanity 公钥就是「带指定前缀的公钥」，比如：

```text
Hello7xQ9k2...   ← 以 Hello 开头
```

这就像车牌选号：号码本身不影响功能，但看着舒服、方便在配置里一眼认出哪台是哪台。

## 为什么只能暴力搜索

因为公钥 ≈ 私钥经过单向函数后的随机结果，想让公钥以 `Hello` 开头，唯一的办法就是：

```text
循环：
    随机生成一个候选私钥
    算出它的公钥
    if 公钥以 "Hello" 开头:
        收工！
```

每次尝试命中的概率是 1/64ⁿ（n 是前缀长度，下一节细算），所以要试成百万上亿次。CPU 一次算一个太慢，这正是 GPU 的用武之地——第 3.7 节会解释为什么 GPU 特别适合干这个。

## 安全说明

- vanity 搜索**不削弱**安全性：搜出来的私钥仍然是 256 位随机数，只是它的公钥恰好好看；
- 但有一条铁律不变：**私钥必须自己生成、自己保管**。千万不要用别人帮你搜的私钥——对方见过私钥就能冒充你。这也是我们要自己写、自己跑这个程序的原因。
