# 6.6 命中回传：atomic_inc 与 64 个 slot

这节写 kernel 的搜索入口 `vanity`，并解决一个并发问题：成千上万个 work-item 里可能有好几个同时命中，它们往哪写结果？

## vanity 入口完整代码

接在 `derive_key` 后面（文件里 `derive_key` 在两个入口之前）：

```c
// ---------------- 入口 ----------------

// 前缀搜索：命中则把私钥（4 个 u64）写入 keys[slot*4 .. slot*4+3]
__kernel void vanity(u64 seed,
                     __constant const u8 *pat,
                     __constant const u8 *mask,
                     u32 patlen,
                     __global u32 *found,
                     __global u64 *keys) {
    u64 gid = (u64)get_global_id(0);
    u64 w[4];
    derive_key(seed, gid, w);

    u8 pub[32];
    wg_pubkey(w, pub);

    for (u32 i = 0; i < patlen; i++) {
        if ((pub[i] & mask[i]) != pat[i]) return;
    }

    u32 slot = atomic_inc((volatile __global u32 *)found);
    if (slot < 64) {
        keys[slot * 4 + 0] = w[0];
        keys[slot * 4 + 1] = w[1];
        keys[slot * 4 + 2] = w[2];
        keys[slot * 4 + 3] = w[3];
    }
}
```


> 💡 补给：`(volatile __global u32 *)found` 是 C 的强制类型转换。OpenCL 1.2 的 `atomic_inc` 要求参数带 `volatile` 修饰（向编译器承诺这块内存会被并发修改，不许缓存优化），而我们声明的 `found` 没有它，所以转换一下以满足函数签名。
## 参数与地址空间

这是 6.3 节预告的「指针坑」正面现场：

- `__constant const u8 *pat`：指向常量区的只读数组。`__constant` 区的数据对所有 work-item 共享、有专门缓存，最适合 pat/mask 这种「人人要读、从不修改」的参数；
- `__global u32 *found` / `__global u64 *keys`：指向显存主区，可读可写，所有 work-item 都能访问；
- `seed`、`patlen` 是标量，按值传。

宿主侧（第 7 章）创建 buffer 和 `set_arg` 的顺序必须和这里一一对应。

## atomic_inc：发号机

命中后的写入冲突这么解决：`found` 是显存里的一个计数器，`atomic_inc(found)` 是**原子操作**——每个调用它的 work-item 拿到一个互不相同的旧值（0, 1, 2, ...），就像排队领号。拿到号 `slot` 后写进 `keys[slot*4..slot*4+4]`，谁也不会覆盖谁。

> 💡 补给：「原子」= 不可被打断。如果两个 work-item 同时执行普通版的 `*found = *found + 1`，可能都读到 5、都写回 6——丢一个号，两个命中写进同一格。atomic_inc 由硬件保证不丢不重。

## 为什么限制 64 个 slot

一轮 2²² 个候选，期望命中数 = 2²² / 64ⁿ。n≥3 时一轮几乎不可能凑满 64 个，但理论上可能爆。所以：

- kernel 侧 `if (slot < 64)`：超出的命中**照常计数**（found 继续涨）但不再写数组，防止越界踩显存；
- 宿主侧读回后取 `min(found, 64)`，只解析实际写下的部分。

计数器和槽位分离的设计让两侧都不丢信息：found 是真实命中数，keys 里是前 64 个。

## 小结

`vanity` = derive_key → wg_pubkey → 掩码比较 → 原子领号写入。剩下一个入口 `selftest_keys`，下节写完 kernel 就齐了。
