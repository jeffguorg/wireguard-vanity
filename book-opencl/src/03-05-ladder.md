# 3.5 Montgomery ladder

这节讲 X25519 的主体算法：Montgomery 梯子。它用 255 步完全固定的「舞步」算出 k·G 的 u 坐标，是整本书循环次数最多、最该看懂的循环。

## 四个寄存器

梯子维护两个「点」（只存 u 坐标，且用分数形式 x/z 表示，避免除法）：

- `(x2, z2)`：当前累加结果，初始 = 点 1 的形式 `(1, 0)`；
- `(x3, z3)`：比前者「多一倍基点」的辅助点，初始 = 基点 `(9, 1)`。

真正的公钥坐标是 `x2/z2`，最后做一次除法（用求逆实现）得到。

## 每位的固定舞步

从标量 k 的最高位（第 254 位）扫到最低位（第 0 位），每一位执行**完全相同**的一组域运算。用第 4 章会定义的函数写出来，每一步长这样：

```text
a  = x2 + z2;  aa = a²;  b = x2 − z2;  bb = b²;  e = aa − bb
c  = x3 + z3;  d  = x3 − z3
da = d·a;      cb = c·b
x3 = (da + cb)²;  z3 = x1·(da − cb)²
x2 = aa·bb;       z2 = e·(aa + 121665·e)
```

（x1 是基点的 u 坐标，恒为 9；121665 是曲线参数派生的常数。）

这就是传说中的「ladder step」：8 次域加/减 + 4 次乘法 + 2 次平方 + 1 次常数乘。255 位 × 每步这么多 = 每个候选密钥约 1000 次乘法 + 1000 次平方，性能命脉全在这里。

## cswap：用掩码代替分支

每一位还有一个细节：根据当前 bit 是 0 还是 1，要「条件交换」 (x2,z2) 和 (x3,z3) 的内容。直接写 `if` 有两个问题：CPU 上有计时侧信道；GPU 上同一批 work-item 走不同分支要串行执行两边。所以用**位掩码**实现无分支交换：

```text
mask = 0 − swap        // swap=1 → mask 全 1；swap=0 → mask 全 0
t    = mask & (a ^ b)  // swap=1 时 t = a^b，否则 t = 0
a ^= t;  b ^= t        // t=a^b 时恰好互换；t=0 时不变
```

> 💡 补给：`x ^ y ^ y = x`，所以 `a ^= (a^b); b ^= (a^b)` 之后 a、b 正好互换。mask 全 0 时 t=0，两个异或什么都不做。三步下来，swap 是 1 就交换、是 0 就原样——没有 if。

循环里还有个 `swap ^= bit; ...; swap = bit` 的小技巧：它判断的是「当前位和上一位是否不同」，4.8 节看代码时对一眼。

## 小结

- 255 步固定流程 ×（几个域运算），不看懂乘法也能默写结构；
- 无分支 cswap 让 GPU 所有 work-item 步调一致，没有分化损失；
- 循环结束后还差最后一步：u = x2 · z2⁻¹，求逆下节讲。
