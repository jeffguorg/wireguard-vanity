# 8.2 调优方向与练习题

最后一节：几个可以动手试的调优方向，以及由浅入深的练习题。

## 调优方向

**1. 轮大小（`--round-log2`）**

默认 22（每轮 2²² ≈ 400 万候选）。调大：每轮跑得久、宿主的调度开销占比更低，但单轮延迟变长（按 Ctrl-C 或命中后要等本轮结束才响应）；调小则相反。在 20～24 之间试试，看速率有没有变化——通常差别不大，因为调度开销本来就小。

**2. local size**

我们发射时只设了 global size，local size 交给驱动选。可以用 `set_local_work_size` 显式指定（64/128/256 各试一档），个别驱动/架构组合下会有几个百分点的差别。work-item 之间无协作，这是纯调度参数。

**3. 32-bit limb 设想**

本书用 10×u64（radix 2^25.5）。GPU 的 32 位乘法通常是全速、64 位乘法要拆指令，所以一个值得尝试的改造是 20×u32 limb（同 26/25 交替，用 u32 存储、u64 累加乘积）。改动集中在 fe 层，梯子不动。这是 ref10 原始形态（它本来就是 32 位整数写的），适合作为进阶练习。

## 练习题

1. **后缀匹配**：把「前缀匹配」改成「后缀匹配」。提示：改 `from_prefix` 里拼字节的起点，kernel 的比较循环跟着动。
2. **多前缀**：一次搜多个前缀（比如 `Hi` 或 `Yo` 都算命中）。提示：传 pat/mask 数组 + 命中时记录是第几个前缀。
3. **大小写不敏感**：前缀 `hello` 匹配 `Hello`/`HELLO`。提示：掩码技巧不够用了，想想每个字符对应多少种 6-bit 值，回到字节层面怎么表达。
4. **命中分布统计**：改宿主程序，记录每次命中发生在第几轮，画个直方图，和几何分布的理论曲线对一对。
5. **读 vulkan/ 目录**：仓库里还有一条 Vulkan + GLSL 的实现路线，域运算设计完全一致。读完本书的你已经有能力对照看懂它——试试把 kernel.cl 和 vulkan 的 shader 逐函数对一遍。

## 结尾

走到这里，你从「没写过 GPU 程序」到拥有一个三层验证、实测 10.8 M keys/s 的密码学暴力搜索器。回头看你亲手写下的三份代码：fe.rs 的进位链、kernel.cl 的梯子、main.rs 的队列调度——它们同构、互相印证。这套「先 CPU 参考实现钉死正确性，再 1:1 移植到 GPU，最后对拍验证」的方法论，可以搬到任何想把计算搬上显卡的问题上。
