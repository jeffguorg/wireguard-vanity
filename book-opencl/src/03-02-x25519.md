# 3.2 X25519 是什么

这节建立对 X25519 的直觉：私钥是一个数，公钥是一个点，从数到点容易、从点到数不可能。不推导任何公式，放心读。

## 椭圆曲线的最小直觉

想象一条特殊的曲线（Curve25519），上面的点可以做「加法」：点 + 点 = 点。于是可以定义「点的乘法」：`k·P` 就是把点 P 自己加 k 次。

- **私钥**：一个 256 bit 的整数 k；
- **公钥**：把固定的基点 G「加 k 次」得到的那个点的坐标，即 `k·G`。

从 k 算 `k·G` 很快（有聪明的算法，3.5 节的梯子）；但从公钥反推 k，只能一个一个试，2²⁵⁵ 量级的尝试——这就是单向性，WireGuard 安全性的根基。

## X25519 的具体形态

X25519 是 RFC 7748 标准化的密钥交换函数，细节我们只需要记住四条：

1. 曲线的所有运算都在**模 p = 2²⁵⁵ − 19** 的有限域里做（下两节的主角）；
2. 只用点的 **u 坐标**（x 坐标），不算 y——省一半计算量；
3. 基点固定为 **u = 9**。WireGuard 只需要 `X25519(私钥, 9)`，所以我们的代码也只实现这一种；
4. 私钥在使用前要做 **clamp**（钳位）：清掉最低 3 bit、清掉最高 bit、置位次高 bit。这是 RFC 的规定，照做即可。

> 💡 补给：clamp 的作用是保证标量是 8 的倍数且高位固定，消除小子群攻击的隐患。写成字节操作就是 `k[0] &= 248; k[31] &= 127; k[31] |= 64`，4.8 节会看到原样代码。

## 和暴力搜索的关系

回到我们的循环：

```text
候选私钥 k ──X25519(k, 9)──► 公钥（32 字节）──base64──► 44 字符
```

每尝试一个候选，就要做一次完整的 X25519。一次 X25519 ≈ 255 轮「梯子步」+ 一次域求逆（3.5、3.6 节），每轮又是若干次域乘法和平方。算下来每个候选要做约两千次 255 bit 大数乘法——这就是为什么快不快完全取决于域运算写得好不好，也是为什么要动用 GPU。

## 小结

- 公钥 = `X25519(私钥, 基点9)`，单向；
- 所有计算在 GF(2²⁵⁵−19) 里，接下来三节把这个域讲透。
