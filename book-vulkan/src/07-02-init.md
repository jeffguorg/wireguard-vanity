# 7.2 初始化：挑一块支持 shaderInt64 的独显

这节写 main.rs 的常量和 `init()`：把 5.1 节的四层对象（library → instance → physical device → device → queue）挨个建出来。

## SPIR-V 字节、上限、Push 结构体

接在 7.1 的 import 清单之后（`fn main() {}` 占位仍在文件末尾）：

```rust
/// build.rs 用 glslangValidator 编译产物
const SHADER_SPV: &[u8] = include_bytes!(concat!(env!("OUT_DIR"), "/shader.spv"));
const SELFTEST_SPV: &[u8] = include_bytes!(concat!(env!("OUT_DIR"), "/selftest.spv"));

/// 每轮最多回收的命中数量（与 shader 中 slot < 64 对应）
const MAX_HITS: usize = 64;

/// push constant 布局，必须与 shader.comp 中的 `Push` 块一致
#[repr(C)]
#[derive(Clone, Copy, vulkano::buffer::BufferContents)]
struct Push {
    seed: u64,
    patlen: u32,
    pat: [u32; 11],
    mask: [u32; 11],
    pad: u32, // 对齐到 8 字节（104），与 shader 中 Push 块一致
}
```

💡 **补给：include_bytes! 与 concat!。** `include_bytes!("path")` 在编译期把文件字节嵌进可执行文件，类型是 `&[u8]`；路径参数必须编译期可知，所以用 `concat!` 拼 `OUT_DIR`。7.1 的 build.rs 把 `.spv` 放进 OUT_DIR，这里再把它们吃回来——可执行文件自包含，不需要附带 .spv 文件。

`#[repr(C)]` 让字段按 C 顺序紧凑排列；`pad` 的道理在 6.2 节讲透了。`BufferContents` derive 是 vulkano 的要求：能被推进 push constant / buffer 的类型都要实现它。

## init()

> 📝 位置提醒：按 7.1 末尾的地图，`Gpu` 与 `init()` 在文件中位于 7.3 节三个 helper 函数**之后**。现在可以先接在 Push 结构体后面写，7.3 节会把 helper 插到 Push 与 Gpu 之间。

```rust
struct Gpu {
    device: Arc<Device>,
    queue: Arc<Queue>,
    queue_family_index: u32,
}

fn init() -> Result<Gpu, Box<dyn std::error::Error>> {
    let library = VulkanLibrary::new()?;
    let instance = Instance::new(library, InstanceCreateInfo::default())?;

    let physical = instance
        .enumerate_physical_devices()?
        .filter(|p| p.supported_features().shader_int64)
        .max_by_key(|p| match p.properties().device_type {
            PhysicalDeviceType::DiscreteGpu => 3,
            PhysicalDeviceType::IntegratedGpu => 2,
            _ => 1,
        })
        .ok_or("没有支持 shaderInt64 的 Vulkan 设备")?;
    eprintln!("使用设备: {}", physical.properties().device_name);

    let queue_family_index = physical
        .queue_family_properties()
        .iter()
        .position(|q| q.queue_flags.contains(QueueFlags::COMPUTE))
        .ok_or("没有支持 compute 的队列族")? as u32;

    let (device, mut queues) = Device::new(
        physical,
        DeviceCreateInfo {
            queue_create_infos: vec![QueueCreateInfo {
                queue_family_index,
                ..Default::default()
            }],
            enabled_features: DeviceFeatures {
                shader_int64: true,
                ..DeviceFeatures::empty()
            },
            ..Default::default()
        },
    )?;

    Ok(Gpu {
        device,
        queue: queues.next().unwrap(),
        queue_family_index,
    })
}
```

💡 **补给：eprintln! 与输出分流。** `eprintln!` 打印到 **stderr** 而不是 stdout。本书的约定：设备信息和进度（「已尝试 … 次」这类）走 stderr，搜到的密钥走 stdout——这样 `cargo run --release -- hSD > hits.txt` 重定向时，文件里只收集密钥，进度照常显示在终端。

逐段看：

1. `VulkanLibrary::new()` 加载 libvulkan.so；`Instance::new` 建实例。纯 compute 不需要任何实例扩展，`default()` 就够。
2. 挑设备：`enumerate_physical_devices()` 列出所有显卡，迭代器链先 `filter` 出支持 `shader_int64` 的，再 `max_by_key` 给独显打 3 分、核显 2 分，取最高——双显卡机器上自动选独显。
3. 找队列族：`position` 找第一个带 `COMPUTE` 标志的族，拿到下标。
4. `Device::new` 开户：声明要用这个队列族、启用 `shader_int64` 特性（shader 里的 `uint64_t` 就靠它）。返回值是 `(device, 队列迭代器)`，`queues.next()` 取出我们申请的那条队列。

💡 **补给：`Box<dyn Error>`。** 函数返回 `Result<Gpu, Box<dyn std::error::Error>>`——「错误是任何一种实现了 Error 的东西」。vulkano 各调用返回的错误类型五花八门，Box 统一装起来，配合 `?` 一路向上抛。`ok_or("...")` 把 `Option` 变 `Result`（6.2 节补给过）。

跑一下试试：`cargo check`（真正的 main 还没写，靠末尾的 `fn main() {}` 占位撑着）。看到编译通过、且 build.rs 没有报 glslang 错误，本节就成了。
