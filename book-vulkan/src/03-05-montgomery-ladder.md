# 3.5 Montgomery ladder

这节讲 X25519 的核心循环：怎么用 255 轮固定运算算出 k·u，以及为什么每轮末尾有个「假交换」。

## 梯子：按位爬山

要算 k·u（k 是 255 bit 私钥），把 k 按二进制从高位到低位逐位处理。维护两个「相差一格」的点：

- 点 A = m·u，点 B = (m+1)·u（m 是已处理前缀的值）。

每看 k 的一位，m 左移一位（相当于翻倍）：新的一位是 0 就把 A 翻倍、B 变成 A+B；是 1 就反过来。因为 A、B 永远只差一格，「A+B」这种加法可以用**差分公式**只算 u 坐标——不需要知道点的完整坐标，这就是 Montgomery 曲线的省法。

255 位扫完，A 就是 k·u。每轮干的事固定：4 次域乘、3 次域平方、若干加减，外加一次常数 121665 的乘法（公式里的 a24）。

## clamp：私钥进门前的三道处理

RFC 7748 规定私钥在使用前必须 clamp：

```text
k[0]  &= 248   // 清最低 3 位：保证私钥是 8 的倍数，防小子群攻击
k[31] &= 127   // 清最高位：保证 < 2^255
k[31] |= 64    // 置次高位：保证私钥的最高位固定在 254 位
```

所以梯子固定从第 254 位扫到第 0 位，255 轮整。我们的私钥派生函数直接以 u64 运算完成 clamp 的等价效果（清低 3 位 = `&= !7`）。

## cswap：没有分支的交换

梯子里「这一位是 0 还是 1」决定两个点谁翻倍——直接写 `if` 会让执行路径取决于密钥。CPU 上这叫侧信道泄漏；GPU 上分支还会让同一线程组里的线程走不同路径（divergence），白白变慢。

解决办法是 **cswap**（条件交换）：用掩码代替分支。`swap` 为 1 就交换两个变量，为 0 不动：

```text
mask = 0 - swap          // swap=1 → mask 全 1；swap=0 → mask 全 0
t = mask & (a ^ b)       // 只在 swap=1 时取出差异位
a ^= t;  b ^= t          // 有差异位就两边同时翻转 = 交换
```

三次异或交换法的常数时间版本，CPU 和 GPU 上都只要 10 次循环（每个 limb 一次）。

## 收尾：一次求逆

梯子的状态是投影坐标 (x2, z2)，真正的 u = x2 / z2。有限域里「除法」= 乘以 z2 的逆元——下一节讲逆元怎么算，它是整个 X25519 里最贵的一步（但每个密钥只算一次）。
