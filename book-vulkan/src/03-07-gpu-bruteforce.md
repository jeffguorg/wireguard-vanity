# 3.7 GPU 为什么适合穷举

最后一节背景：为什么这个任务要搬上 GPU，以及 GPU 编程和 CPU 编程的思维差异。

## 这个任务的三个特征

1. **海量独立子任务**：每个候选私钥的「派生 → X25519 → 比对前缀」完全不依赖其他候选，零通信；
2. **几乎无内存访问**：全程寄存器级计算，不读大表、不写大文件；
3. **ALU 密集**：每个密钥约 255 轮 × 若干次 10-limb 乘加，纯整数算力消耗。

这种「尴尬并行」（embarrassingly parallel）负载是 GPU 的甜点区。

## GPU 和 CPU 的取舍

CPU 核心：少数几个强大的核，擅长分支复杂、依赖多的串行逻辑。
GPU：成千上万个「笨」核，单个核慢，但大家一起跑同样的程序。

一次 X25519 在 CPU 上单核跑约 1~2 微秒；RX 7900 XTX 有 6144 个流处理器，几万个线程同时压上去，吞吐就到每秒数百万次。本书实测约 4.9 M keys/s。

## 思维转换清单

| CPU 习惯 | GPU 现实 |
|---|---|
| `main()` 跑一遍 | shader 的 `main()` 被几十万线程**同时**各跑一遍 |
| 函数参数/返回值 | 参数走 push constant / buffer；结果写进共享 buffer |
| `println!` 调试 | 没有。靠写回 buffer + CPU 对拍 |
| 指针、引用 | 没有指针；数组按值传，`inout` 标记可改参数 |
| 64 位整数天然支持 | 需要声明扩展 + 设备特性（shaderInt64） |

## 一个线程在干什么

每个 GPU 线程分到一个全局编号 `gid`（0, 1, 2, …），然后：

```text
1. 用 seed + gid 派生一个私钥（splitmix64，保证互不重复）
2. 算这个私钥的公钥（完整的 X25519）
3. 比对前缀，命中就把私钥写进结果 buffer
```

同一时刻几万个线程各算各的，一轮 dispatch 就是几百万次尝试。CPU 宿主程序只负责：发参数、按启动按钮、等结果、打印命中的私钥。

## 为什么用 Vulkan 而不是 CUDA/OpenCL

- CUDA 只支持 NVIDIA，我们的机器是 AMD；
- OpenCL 其实也行（本仓库就有一份 OpenCL 实现），但 Vulkan 驱动在现代 Linux 上是显卡标配，且 SPIR-V 生态更新更活跃；
- 顺带，Vulkan 的「显式」风格（所有资源亲手创建）虽然啰嗦，学完一次，对 GPU 工作原理的理解是扎实的——这就是下一章之后的旅程。
