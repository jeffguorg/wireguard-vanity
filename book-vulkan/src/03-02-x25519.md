# 3.2 X25519 是什么

这节讲 X25519 的定位和形状：它接收什么、吐出什么、内部大致经历哪几步。公式细节留给后面三节。

## 一句话版本

X25519 是 RFC 7748 定义的密钥交换函数：

```text
公钥字节 = X25519(私钥字节, u 坐标)
```

WireGuard 只用到一种形式：**u 坐标固定为基点 9**，即 `公钥 = X25519(私钥, 9)`。我们的 CPU 和 GPU 实现都只支持这个形式，代码因此简单很多。

## 它在椭圆曲线上做什么

不用懂椭圆曲线理论，记住这个模型就够：

- 有一条公开的曲线（Curve25519），上面的「点」用一个模 2^255−19 的数（u 坐标）近似代表；
- 私钥是一个 255 bit 的整数 k；
- X25519(k, u) = 把点 u 「加自己 k 次」得到的新点的 u 坐标，记作 k·u。

「加 k 次」不是真加 k 次（k 有 255 bit，加到宇宙热寂也加不完），而是用 **Montgomery ladder**（梯子算法）把 k 按二进制拆开，255 轮、每轮固定几次乘法和平方就算完。3.5 节专门讲它。

## 为什么单向

正向：给 k，255 轮固定运算就得到 k·u，毫秒级。
反向：给 k·u 求 k（椭圆曲线离散对数），没有已知的高效算法——这就是「公钥公开也无妨」的数学基础，也是 vanity 搜索只能暴力枚举私钥的原因。

## 全程在模 2^255−19 下进行

梯子里的每一次加法、乘法、平方，结果都要对素数 p = 2^255−19 取模。也就是说 X25519 的全部算术都发生在**有限域 GF(2^255−19)** 里：

- 「加法」「乘法」= 普通整数运算后 mod p；
- 「除法」= 乘以逆元（3.6 节）；
- 255 bit 的数放不进一个 u64——怎么表示、怎么进位，是 3.3、3.4 两节的内容。

## 一次 X25519 的配料表

```text
输入: 32 字节私钥（先 clamp）
1. 初始化梯子的四个状态变量
2. 255 轮 × (几次域加/减/乘/平方 + 条件交换)
3. 最后做一次域求逆，把投影坐标转回普通坐标
输出: 32 字节公钥（小端序）
```

GPU 上每个线程独立完成这整个流程，互不说话——这正是它适合并行穷举的原因（3.7 节）。
